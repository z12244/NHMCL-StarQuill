# 内存与崩溃诊断

## 内存设置

在「启动设置 → Java 与内存」勾选「启动游戏前进行内存优化」，点击「保存设置」。开关默认关闭。启用后，每次游戏文件准备完成、Java 进程启动前执行一次，全局适用于各版本。

启动器在主进程执行 V8 垃圾回收，并清理页面中闲置的图片等内存缓存。运行日志显示主进程 JS 堆在回收前后的占用。回收效果取决于启动器当时的内存使用情况。遇到回收错误会记录原因并继续启动游戏。

0.8.2 曾停用调用隐藏 PowerShell 的旧实现，相关历史见 [UPDATE-0.8.2.md](UPDATE-0.8.2.md)。升级后需主动勾选才会启用新版优化。

内存滑块旁显示「当前可用 X.X GB」。全局设置还有已用 / 总量和已用内存条。版本独立内存设置也显示当前可用值。读取本机系统内存数据，设置页可见时每 2 秒刷新；切换到其他页面或隐藏启动器时停止。内存配置上限仍来自总物理内存，当前可用量仅作参考，不会自动改动你保存的分配值。

这不改变 Minecraft 官方版本清单的更新规则：仍只在每次打开启动器时自动检查一次，保留手动刷新。

## 崩溃报告

游戏非正常退出、收到非主动终止信号，或退出时发现本次新增 / 更新的崩溃文件，自动生成：

```text
.minecraft/.starquill/crash-reports/时间-随机编号.zip
```

ZIP 包含本次启动器输出、当次更新的 latest.log / debug.log、最多 6 份新出现或更新的 Minecraft 崩溃文件与 hs_err_pid 日志，以及「分析报告.txt」和 report.json。每份文件日志最多 16 MiB，本次启动器输出最多 32 MiB；普通日志保留末尾，过大崩溃文件保留开头与末尾。只收集当前游戏目录的相关日志，不打包存档或账号配置。每次使用独立文件名，不覆盖以前的报告。

界面顶部出现「查看分析」，运行日志页可查看原因线索、建议并点击「定位日志压缩包」。重启启动器后可继续查看当前游戏根目录最近一份报告；历史报告仍保存在上述目录。

分析覆盖堆内存不足、系统 / 本地内存不足、Java 不兼容、前置缺失、重复模组、Mixin 冲突、OpenGL / 显卡相关错误、磁盘空间不足与 Java 本地崩溃。它是基于关键词的初步判断；无法识别时明确提示未确定原因，不仅根据退出码猜测具体模组。正常退出、点击「结束游戏」或主动关闭启动器不自动导出崩溃报告；下载 / 取消准备也不当作游戏崩溃。

报告只保存在本机，不自动上传。写入前过滤常见令牌、密码和当前账号令牌；分享前仍需检查玩家名、服务器地址与本地路径等信息。自动保存失败时显示提示，仍可使用原来的「导出日志」按钮。

## 本次验证范围

只做代码语法、界面元素与 IPC 连接检查、限定范围的内存 / 崩溃日志样例验证和打包核对。本次不启动游戏，不重新进行加载器、整合包、账号和网络下载深度测试。详细结果见发行目录 verification.json。

实现参考：[Windows EmptyWorkingSet](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-emptyworkingset)、[Electron ProcessMetric](https://www.electronjs.org/docs/latest/api/structures/process-metric)。


0.8.1：启动参数指定游戏目录内 hs_err_pid%p.log，关闭快速异常省略调用栈。异常退出后等待 1.5 秒收尾，并仅按本次 Java PID 补查系统临时目录。记录 Java 路径、系统版本、进程 PID、启动及退出时可用内存，输出退出码的原始、有符号与十六进制表示。未生成的堆栈无法恢复；外部强制终止、原生故障等并不一定留下 Java 异常。新增采集对下一次启动生效，无法补回旧报告缺失的信息。
